# Бенчмарк потоковых защитных механизмов

Этот репозиторий посвящён модерации ответов больших языковых моделей в потоковом режиме. При потоковой генерации ответ показывается пользователю постепенно — по одному токену или небольшими фрагментами. Поэтому защитный механизм должен принимать решение до того, как станет доступен полный ответ. Проект измеряет, как размер проверяемого фрагмента влияет на ложные блокировки, пропуск опасного содержания, объём утечки до блокировки и вычислительную задержку.

## Текущий статус

Этап подготовки данных завершён. На основе
[StreamSafe](https://huggingface.co/datasets/Solitude0630/StreamSafe):

- полные ответы однозначно сопоставляются с размеченными префиксами;
- исходный текст сохраняется без изменений, а спорные случаи попадают в журнал;
- сформирован воспроизводимый поднабор из 500 трасс — 250 `safe` и 250 `unsafe`;
- для опасных трасс вычисляется интервальная граница появления вреда;
- границы переводятся в символы, байты, предложения и токены закреплённого токенизатора Qwen;
- проверяются пересечения между обучающей, проверочной и тестовой частями;
- итоговый поднабор проходит автоматические проверки состава и воспроизводимости.

Полный воспроизводимый выпуск опубликован на Hugging Face:
[Vovarus12go/streamsafe-500-boundaries](https://huggingface.co/datasets/Vovarus12go/streamsafe-500-boundaries).
Он содержит 500 исходных запросов и ответов StreamSafe, метки, категории вреда, границы
префиксов и интервалы первого подтверждённого опасного префикса. Для работы с ним не
нужно отдельно скачивать исходный StreamSafe.

Реализован следующий слой эксперимента:

- токенный адаптер `Qwen/Qwen3Guard-Stream-0.6B` без повторной токенизации префикса;
- однократное получение решения после каждого токена ответа;
- режимы `token`, `chunk_8`, `chunk_16`, `chunk_32`, `sentence` и `full_buffered`;
- строгая и консервативная политики обработки `Controversial`;
- интервальные метрики утечки и задержки;
- сохранение каждой трассы и продолжение прерванного запуска.

## Конвейер эксперимента

```text
готовые 500 трасс на Hugging Face
    ↓
один токенный проход Qwen3Guard по каждому ответу
    ↓
сохранённые трёхклассовые решения по токенам
    ↓
шесть режимов буферизации × две политики безопасности
    ↓
ложные срабатывания, пропуски, утечка и задержка
```

## Быстрый старт

Требуется Python 3.11.

```bash
python -m pip install -e ".[analysis,dev]"
pytest
```

Для запуска Qwen3Guard установите модельные зависимости:

```bash
python -m pip install -e ".[analysis,dev,models,streaming]"
```

Готовый набор загружается одной командой Python:

```python
from datasets import load_dataset

dataset = load_dataset("Vovarus12go/streamsafe-500-boundaries")
```

Основной интерфейс эксперимента — `notebooks/03_streaming_engine.ipynb`. В начале
ноутбука выбирается профиль:

```python
PROFILE = "smoke"  # 10 трасс
# PROFILE = "full"  # все 500 трасс
```

По умолчанию ноутбук читает уже сохранённый smoke-прогон и не загружает модель:

```python
RUN_MODEL = False
```

Чтобы выполнить новый прогон, установите `RUN_MODEL = True`. После завершения можно
вернуть `False` и повторно строить метрики и графики из CSV и Parquet без вычисления
Qwen3Guard.

Промежуточные решения и таблицы сохраняются в
`data/interim/qwen3guard_baseline/` и не попадают в Git.

Результат проверочного запуска настоящей модели на 10 трассах описан в
[`reports/qwen3guard_smoke_summary.md`](reports/qwen3guard_smoke_summary.md). Он
подтверждает работоспособность конвейера, но не используется для исследовательских
выводов.

Технические версии источника и токенизатора сохранены в конфигурациях и манифестах,
но для запуска экспериментов с опубликованными 500 трассами они не нужны.

## Структура репозитория

- `configs/` — версионируемые настройки данных и экспериментов;
- `notebooks/` — поясняющий анализ и визуализации;
- `scripts/` — отдельные команды загрузки, нормализации, выбора и проверки;
- `src/streamguard_bench/data/` — загрузка, инспекция схемы и валидация;
- `src/streamguard_bench/guards/` — общий интерфейс адаптеров защитных моделей;
- `src/streamguard_bench/streaming/` — общий интерфейс потоковых политик;
- `src/streamguard_bench/metrics/` — общий интерфейс метрик;
- `data/fixtures/` — искусственные записи для автономных тестов;
- `reports/` — агрегированные таблицы, графики и текстовые выводы;
- `tests/` — тесты, не требующие доступа к интернету.

## Воспроизведение подготовки данных

Этот раздел нужен только для повторной сборки выпуска из исходного StreamSafe. Для
экспериментов второго этапа его можно пропустить.

Команды выполняются последовательно:

```bash
python scripts/prepare_streamsafe_pool.py
python scripts/build_streamsafe_subset.py
python scripts/validate_streamsafe_subset.py
jupyter notebook notebooks/02_streamsafe_subset.ipynb
python scripts/export_streamsafe_annotations.py --include-source-text
```

Если исходные файлы ещё не загружены, сначала выполните
`python scripts/download_streamsafe.py` и `python scripts/run_data_validation.py`.
Команды выше строят нормализованный пул, выбирают 500 трасс, проверяют квоты и создают
локальную структуру выпуска Hugging Face.

Локальные файлы `data/processed/streamsafe_pool.parquet`,
`data/processed/streamsafe_subset_500.parquet` содержат исходные тексты и не попадают в
Git.

Команда экспорта создаёт структуру выпуска Hugging Face в
`data/processed/huggingface/streamsafe-500-boundaries/`. По умолчанию исходные тексты
не включаются; опубликованный полный вариант воспроизводится с флагом
`--include-source-text`.

## Передача участнику 4

Профиль `smoke` использует 5 безопасных и 5 опасных трасс и проверяет только
работоспособность инфраструктуры. Участник 4 переключает профиль на `full`, получает
6000 строк — 500 трасс × 6 режимов × 2 политики — и выполняет итоговый анализ по частям
набора, категориям и позиции появления вреда. Полные запросы и ответы в публичные таблицы
результатов не записываются.
